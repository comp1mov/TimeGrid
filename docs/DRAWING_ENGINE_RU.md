# Drawing engine: границы первой итерации

19 октября 2026, `28.35.0-drawing.1`, ветка `codex/drawing-engine`.

## Что уже работает

`drawing-geometry.mjs` — чистая модель геометрии, без DOM и без сохранённых frame IDs. Она принимает подготовленные прямоугольники и возвращает попадание/привязку к gap. DOM-адаптер в `main.js` переводит client coordinates в координаты drawCanvas и создаёт карту. Композиция и input используют один снимок. Срок жизни ограничен animation frame плюс явные сбросы на изменения интерфейса; это переходная защита для большого legacy UI.

Пустой FRM явно обозначается размером canvas 0 × 0. `ensureFrameSheet()` синхронизирует только уже существующий sheet; `ensureFrameSheet(true)` разрешает выделение при записи. Запрос undo до первого попадания содержит только размеры и пустую Map. Формат сохранённых рисунков не изменён. В тесте загружается PNG, реально созданный исходной 28.34, и сравниваются RGBA-хэши.

BG по-прежнему имеет отдельные поверхности grid и single. TPL — повторяемый рисунок в системе координат шаблона. FRM — прежний sheet, где slice выбирается по текущему frameIdx. Штрихи, long stroke, слои и экспорт используют существующие кисти. Полной замены хранения или input adapters в этом релизе нет.

## Контракт следующего хранилища — пока проектирование

Минимальная запись рисунка должна содержать:

| Поле | Назначение |
| --- | --- |
| `attachment` | `background-grid`, `background-single`, `template` или `frame` |
| `logicalSize` | Размер системы координат оригинала; смена preview quality его не меняет |
| `sampleOccurrenceId` | Только для FRM: устойчивый ID конкретного вхождения sample в проект |
| `rasterAssets` | Создаваемые по необходимости tiles с координатами и фактическими размерами |
| `dirtyRegions` | Области, требующие обновления preview/export; temporal effects могут расширять их |
| `revision` | Версия рисунка для инвалидирования производных кэшей |

Идентификатор вхождения отличается от номера кадра источника: два вхождения одного исходного кадра могут иметь разные рисунки. Изменение gridCols/порядка DOM не меняет привязку. Atlas остаётся только производным кэшем. Undo хранит предыдущие версии изменённых tiles с ограничением байтов.

Миграция старого sheet должна разрезать его по сохранённым cols/tile sizes и связывать slices с соответствующими вхождениями. Неизвестные/несовместимые привязки сохраняются как orphan assets до явного решения пользователя. Нельзя молча ресэмплировать оригиналы при смене proxy или уничтожать рисунки при новой выборке.

## Перед следующей функциональной версией

1. Исправить обнаруженный Undo на пересечениях границ с отдельным тестом: кисть может затронуть соседний tile раньше его snapshot. Также проверить FRM Clear undo, который в legacy передаёт неверный тип аргумента.
2. Добавить sample occurrence IDs и совместимый import/export до переключения основного хранения.
3. Перенести запись на sparse tiles, измерить память после первого штриха и историю Undo. Текущий выигрыш относится только к пустому FRM.
4. Отдельно проверить физический телефон/планшет: модель, ОС, браузер, finger/pen, multi-touch, capture/cancel, coalesced samples. Синтетический PointerEvent в desktop Edge это не заменяет.
