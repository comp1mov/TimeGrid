# Drawing .4: проверка авторского отзыва о задержке, BG и Spray

26 октября 2026. Документационное исследование, код приложения и публичный релиз не изменены. Текущий стенд остаётся 28.35.0-drawing.4.

Автор сообщил, что в целом рисование работает, но библиотека кажется недостаточной для всей логики TimeGrid; BG не позволяет рисовать вокруг кадров, Spray непонятен, заливки нет. Затем отдельно сообщил о заметном торможении во время рисования. Это уточняет приоритет: сначала отзывчивость и правильная семантика инструментов, затем новые функции.

## Живой ввод

Метод: `probe.cjs`, стандартный Edge 156.0.4314.42 headless, 1440 × 1000, тот же host Windows/Radeon 890M. Новая изолированная страница для каждого случая. Public immutable URLs .3/.4. Grid 96, Width 80, speed off, Stabilizer 50. Один одинаковый путь из 240 synthetic PointerEvent move, отправляемых по rAF, native browser down/up. Итоговая геометрия затронула 16 кадров. Код и raw timings в этом каталоге.

| Вариант | Geometry p95 ms | Render с geometry p95 ms | Интервал callback p95 ms |
| --- | --- | --- | --- |
| .3 hard Round | 0.6 | 2.5 | 17.4 |
| .4 hard Round | 0.5 | 1.9 | 17.5 |
| .4 soft Round 70 | 0.3 | 4.1 | 17.7 |
| .4 Spray | 5.9 | 47.3 | 48.5 |
| .4 soft Spray 70 | 6.5 | 123.3 | 128.3 |

В Spray 39 870 частиц. Render p95 для первой/последней трети жеста: hard Spray 15.1 → 49.6 ms, soft Spray 37.9 → 129.9 ms. Это воспроизводит рост задержки по мере удлинения жеста. Hard Round в этом конкретном прогоне не показал замедления .4 против .3. Один сравнительный прогон не является доказательством ускорения Round и не исключает другие сценарии автора.

RenderMs включает refreshDrafts/geometry, поэтому эти два столбца нельзя складывать. Интервалы rAF и JS timing не являются физическим pen-to-photon или измерением GPU presentation. Физический телефон/перо не использовались.

Причины в исходниках:
- drawing-lab.mjs refreshDrafts вызывает createStroke со всеми накопленными points на каждом rAF.
- makeStamps заново создаёт все частицы и округляет их координаты; gridPlacements снова обходит геометрию.
- stroke-cache setDrafts инвалидирует полный старый и новый bbox, затем повторно рисуются уже пройденные плитки.
- Новый объект draft теряет WeakMap stamp index; spatial index строится заново.
- Soft Spray создаёт radial gradient для каждой частицы при каждом таком рендере.

Старый benchmark с готовыми strokes проверял cold/warm показ и сохранность, а не достаточную отзывчивость активного Spray. Поэтому прохождение прежних тестов не закрывает эту проблему.

## BG: несоответствие существующему TimeGrid

В .4 feed использует gridRect и для BG, drawScene передаёт bg-grid/bg-single в renderer.draw с тем же gridRect; renderer ограничивает рисование его границами. Сам fixture не имеет полей и промежутков внутри composition; область вокруг сетки является только фоном viewport. Рисовать на ней как BG нельзя.

В stable main.js BG canvas рассчитан на draw canvas layout, отдельно от frame tiles, есть underlay и существующий параметр bgLayerAboveDrawings. Комментарии и работа слоя определяют BG как фон вокруг кадров. Значит, это упрощение/ошибка стенда, не ограничение perfect-freehand.

Исправление должно дать BG собственное пространство композиции с полями/промежутками, сохранить его адресацию при zoom/reflow и повторить существующий порядок слоёв. Не просто отвязать clip и начать писать в экранных координатах. Preview/PNG и Save/Open должны включать тот же фон; бесконечный холст не подразумевается.

## Spray: потеря настроек и художественное несоответствие

Stable main.js: начальные sprayScatter=1.5, sprayDotScale=0.1; существующие контролы меняют оба. Формулы: scatter radius=max(2,size×0.95×scatter); baseDotR=max(0.9×dotScale,size×0.10×dotScale).

Lab .4 не хранит эти параметры и не показывает контролы, использует scatter=1 и dotScale=1. Поэтому при сопоставимом size базовый радиус точки около десятикратного относительно stable default, а рассеивание меньше. Нельзя утверждать, что характер прежнего Spray уже сохранён. В .4 также иная пространственная плотность, чем в старой event-dependent кисти; exact artistic parity не проверялась.

Нужно вернуть существующие регулировки и согласованные значения, отдельно оценить плотность/flow. Уже сохранённые .4 stamps нельзя уменьшать или пересоздавать при Open. Новые настройки влияют на новые жесты.

## Роль библиотек и заливка

[perfect-freehand README](https://github.com/steveruizok/perfect-freehand) определяет генератор outline из input points с pressure/streamline, не полноценный painting engine. Его можно оставить для hard Round и использовать общий stroke document с другими операциями.

[Klecks README](https://github.com/bitbof/klecks) перечисляет слои, pressure/stabilizer, touch, paint bucket, кисти, selection и filters. [Embed example](https://github.com/bitbof/klecks/blob/main/examples/embed/example.html) открывает проект width/height/layers с image data и экспортирует PNG/PSD. Это более полный painting editor. Скорость в TimeGrid/96-frame workflow не измерена. Нельзя объявлять его автоматическим решением BG/TPL/FRM, shared geometry, 1F и temporal accumulation. Встраивание готового редактора не является согласованной сменой интерфейса.

Предлагаемая архитектура: единый документ TimeGrid, hard line contours, детерминированные brush operations, фиксированные fill regions, ограниченные производные raster tiles. Растр допустим для локальных масок/текстур; запрет всех raster assets не является целью. Цель: отсутствие гигантских пустых allocation, сохранность и воспроизводимый export.

Заливка по подтверждённому запросу: click внутри замкнутой нарисованной фигуры, по границе active drawing layer. Для FRM/TPL рабочая область кадра, для BG собственная композиция. Контуры/маска области фиксируются с цветом как отдельная Undo-операция. Поиск границы не должен зависеть от текущего уменьшенного preview или заново выполняться на каждом export. Нужно проверить holes, anti-alias edge, полупрозрачность, маленькие разрывы и незамкнутый контур. Для мягкой границы требуется явный threshold; нельзя обещать одинаковую топологию на любом разрешении без этих проверок. Код fill можно исследовать в зрелом редакторе, но совместимость с нашим документом ещё не проверена.

## Следующий предлагаемый объём, до согласования

1. Исправить active-stroke путь: законченная часть не пересоздаётся и не растеризуется на каждом input; обновляется только меняющийся хвост/новые dabs и затронутые области. Стабилизация, opacity overlap, Undo и release не должны давать швы или скачок формы.
2. Уменьшить стоимость soft dabs с кешем небольших отпечатков или пакетным renderer после проверки pixel/visual parity. Worker/GPU рассматриваются по профилю, не как автоматическое обещание.
3. Исправить BG и вернуть существующие параметры Spray. Проверять на полях/промежутках и в экспортируемой композиции, не только в тестовых клетках.
4. Заливка отдельным шагом после измеримой отзывчивости; не наращивать функции поверх текущего лагующего пути. Layout/1F/Long Stroke/Onion и proxy остаются очередью после этого.

Критерии: такой же живой сравнительный прогон, рост стоимости от длины жеста, p95 input/geometry/render, визуальная форма live/final, отмена/повтор, старый Save/Open, текущие слои и физический телефон. Цель 60 Hz в согласованном обычном workload требует укладываться примерно в 16.7 ms; это цель, ещё не достигнутая Spray .4.

В этом проходе только диагностика, raw evidence и план. Новый app version/deploy не создаётся.
