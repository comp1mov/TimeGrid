# Drawing baseline и первая итерация

19 октября 2026. Сравнение неизменённой Local 28.34 (`3dfd4f0`) и `28.35.0-drawing.1`, ветка `codex/drawing-engine`.

## Условия

Windows, headless Microsoft Edge **155.0.4283.62**, viewport 1440 × 1000, DPR 1. Детерминированные растровые кадры 1920 × 1080, quality 0.125 / 0.5, 24 / 96 кадров, 8 колонок, spacing 12, scale 0.48, round brush size 7. Это проверка drawing/render path без декодирования видео и сетевых сервисов. Штрих задаётся 15 MouseEvent-точками от первой до последней ячейки через animation frames; некоторые точки находятся за пределами видимой области браузера. Сентябрьский ручной проход был другим.

`Element.getBoundingClientRect` считает все вызовы за этот штрих, включая композицию. Измеряются также `getFrameAtPoint`, `drawFrameStrokeResampled` и `compositeAllLayers`; время — `performance.now`. Число семплов небольшое (9/13 resampling-вызовов), поэтому p95 здесь равен максимуму. Нулевые короткие durations означают предел разрешения таймера, а не бесплатную операцию.

Чтений rect стало на 93.4–94.3% меньше. Память считается как width × height × 4; это пиксели только FRM, не общий RSS или расход всех слоёв. После первого штриха размер FRM остаётся прежним. Sparse storage ещё не реализован.

Median уменьшился, но p95 улучшился не во всех сценариях: в 96/0.125 новый проход имел выброс 32.4 мс. Результат не подтверждает универсальное ускорение или стабильный FPS. Медиана полной композиции почти та же: 0.2/0.3/0.5/1.0 мс → 0.2/0.3/0.5/0.9 мс. Raster/undo остаются следующими источниками работы; оптимизация DOM не устраняет их стоимость.

## Совместимость

Во всех четырёх сценариях совпали размеры и SHA-256 RGBA для FRM-штриха, PNG save/load, прозрачного export helper, BG, TPL, pen и touch eraser adapters, а также состояния после Undo. Сравнение Undo сохраняет **известную ошибку исходной версии**: 553/7441/695/8870 непрозрачных пикселей остаются после cross-cell undo. Это не проверка «Undo полностью очистил слой».

Дополнительный сценарий 24/0.125 проверяет zoom/pan, смену grid/single, живой frameIdx при неизменной геометрии, 6 колонок, нулевой gap, квадратный target aspect, rotation/mirror. Пиксели BG-single, onion, reference composition, round/spray/pencil/calligraphy, long stroke без fade и TPL bake совпали с 28.34. RNG spray фиксирован только в тесте.

Сохранён [реальный PNG-sheet 28.34](legacy-28.34-frm.png); новая версия загружает его через существующий save-slot loader с нулевого FRM canvas и получает те же пиксели. Это не полный ProjectDocument round-trip: формат проекта и sample occurrence IDs пока не менялись.

Пустой FRM остаётся 0 × 0 после Draw open, очистки, onion, export, сохранения пустого слота и нажатия вне ячеек. Сохранённый пустой слот не содержит PNG blob.

Pen/touch — **синтетические PointerEvent в desktop Edge**. В тесте подменяется capture для синтетического pointerId; реальный pointer capture, multi-touch/cancel, iOS/Safari и физический Pencil не проверены. Mobile performance из этих данных не следует. Long-stroke fade требует отдельной матрицы.

## Файлы и повторение

- `baseline-28.34-expanded.json` — baseline текущего полного теста; источник таблицы выше.
- `drawing-28.35.0-drawing.1.json` — финальный matching run.
- `baseline-28.34.json` — первый проход до добавления расширенной матрицы; сохранён отдельно, в таблице не используется.
- `legacy-28.34-frm.png` — sheet для проверки старых пикселей.

Из Drawing worktree, при установленном Playwright (или с `PLAYWRIGHT_MODULE`, указывающим на пакет):

```powershell
npm test
npm run build
npm run test:drawing
```

Runner сам запускает локальный Vite на 5186 и закрывает свой процесс. `TEST_PORT` меняет порт. По умолчанию Drawing сравнивается с сохранённым baseline. Новый baseline снимается тем же runner с `TEST_ROOT`, указывающим на неизменённую 28.34, и `DRAWING_OUTPUT`, указывающим на новый JSON; версия читается из проверяемого checkout. Не переписывать исторические результаты при выпуске следующей версии.
