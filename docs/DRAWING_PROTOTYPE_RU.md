# Drawing Lab 28.35.0-drawing.3

26 октября 2026. Ветка `codex/drawing-engine`. [Текущий стенд](https://comp1mov.github.io/TimeGrid/drawing/28.35.0-drawing.3/drawing-lab.html). [Проверки и сырые данные](drawing-evidence/2026-10-26-perfect-freehand-3/README.md).

## Граница выпуска

Выпуск исправляет только отдельный Drawing Lab. Обычный TimeGrid этой ветки остаётся 28.35.0-drawing.2; стабильный TimeGrid остаётся 28.34. Cloud не участвует. Новый стенд не является новым продуктом или новой логикой работы TimeGrid. Grid и Single остаются двумя видами одного банка кадров.

Стенд содержит 96 сгенерированных кадров. Реальное видео, sampling, старые растровые рисунки, эффекты, аудио, старые кисти, long stroke/trail/bake и полный ProjectDocument сюда ещё не подключены. Его JSON нельзя считать проектом TimeGrid.

## Авторский отзыв и найденные причины

Автор сообщил: линия выглядит ломаной, нет понятной настройки ширины и плавности, при Single видна странная сетка. Отдельно отметил другой шрифт, непонятные ссылки между приложениями и нежелательное обновление обычного приложения вместе со стендом.

В drawing.2 входной жест сначала делился на сегменты ячеек, после чего каждый сегмент отдельно проходил через perfect-freehand. Это перезапускало streamline, pressure и концы штриха на каждой границе. Smoothing регулировал край контура; стабилизация траектории была жёстко задана 0.25. Полигон рисовался прямыми lineTo. Регулятор Size существовал и был подключён, но не было числового ввода и объяснения единиц; точную причину отсутствия реакции в браузере автора независимо воспроизвести не удалось.

При визуальной проверке drawing.3 обнаружен второй дефект: соседние растровые плитки при дробном масштабе смешивались с фоном на общих границах. В Single толстый штрих получал видимую внутреннюю сетку. Предыдущий тест alpha на целочисленном масштабе этого не проверял.

Предыдущие успешные тесты сохранения/памяти не означали принятия художественного качества. Этот пробел зафиксирован, прежние результаты не переименованы.

## Модель оригинала и размещений

`stroke-document.mjs`: format timegrid-strokes, schema 2, engine perfect-freehand@1.2.3.

- Логический кадр 1024 × 576, лист 8192 × 6912. Эти координаты не зависят от viewport, DPR или zoom.
- Один штрих хранит ID, исходные x/y/pressure, параметры кисти, фиксированный outline и renderer. Геометрия после записи заморожена.
- Grid-жест FRM/TPL создаётся в пространстве `sheet` и проходит через getStroke целиком. Переход в ячейку не запускает новую кисть.
- Размещения хранят только целевую поверхность и перевод координат x/y. Они ссылаются на одну геометрию. Данные точек и контур не размножаются на 96 кадров.
- FRM получает адреса frame-0…frame-95. TPL получает несколько размещений одного штриха в общей поверхности tpl. Их порядок сохраняется, включая наложение полупрозрачных следов.
- BG сохраняет отдельные bg-grid и bg-single. Single FRM/TPL работает в координатах одного кадра. При playback смена кадра создаёт новый временной сегмент внутри той же Undo-транзакции.
- Затронутые ячейки определяются по готовой форме кисти, включая её толщину, а не только по центральной линии или большому bbox. Для отбора квадратичный контур аппроксимируется с допуском 0.25 логического пикселя и расширением границы 0.5. Это не упрощает сохраняемый outline.
- Пространственный индекс содержит render instances, bbox и ссылки на штрих. Query возвращает операции в порядке ID и размещения. Он не дублирует массивы точек.

Текущие frame-N являются адресами fixture. Перед интеграцией нужны стабильные SampleOccurrence ID для реального sampling, повторов и изменения сетки.

## Форма кисти и ввод

Контур отображается квадратичными сегментами через середины соседних точек, по [примеру perfect-freehand](https://github.com/steveruizok/perfect-freehand). Повторное открытие не вызывает getStroke для сохранённой геометрии.

- Width: 2…180 логических пикселей кадра, slider и числовое поле. Подпись показывает приблизительную ширину на экране. В Grid след закономерно выглядит меньше, чем в Single.
- Edge smoothing регулирует край. Stabilizer отдельно регулирует streamline траектории от 0 до 1. Большое значение задерживает след относительно руки.
- Pen pressure использует давление PointerEvent пера. Для мыши/пальца по умолчанию постоянная ширина. Vary with speed отдельно включает библиотечную симуляцию давления.
- Настройки фиксируются при начале жеста; изменение регулятора не меняет ранее сохранённые штрихи.
- Pointer Events, pointer capture и coalesced samples. Rect читается при начале/изменении layout, а не для каждой ячейки на каждой точке.
- Геометрия Grid/Single и параметры фиксируются на pointerdown. Resize, смена вида, blur, pointercancel отменяют draft, чтобы не склеивать несвязанные жесты.
- Pinch двумя пальцами отменяет рисующий draft и меняет вид. Pan, wheel и Fit не меняют документ.
- Геометрия draft пересчитывается по rAF. Завершённые штрихи не пересчитываются. Pressure=0 на отпускании пера не создаёт внезапно тонкий кончик; используется последнее давление.
- Невидимые жесты за пределами всех поверхностей не коммитятся. Лимит длинного жеста также обрабатывается на pointerup.

Это одна freehand-кисть. Не заявляется сохранение характера всех старых кистей TimeGrid до их отдельной интеграции и сравнения.

## Растровый кеш и устранение сетки

`stroke-cache.mjs`: sparse tiles 256 raster pixels с полем 2 px, LOD степенями двойки 1/32…4, LRU 24 MiB. Пустая поверхность не выделяет raster backing. Кеш производный и не входит в файл рисунка. Path2D cache ограничен 1024 записями.

Плитки отрисовываются с явным CPU readback-friendly Canvas2D. Рендерер сохраняет bleed за пределами поверхности, затем ограничивает итоговую композицию. При выводе соседние плитки получают непересекающиеся области целых device pixels. Координаты выборки внутри bleed пересчитываются по той же логической трансформации. Это убирает смешивание с фоном на дробных стыках без отдельного растягивания каждой плитки.

Два экранных буфера учитываются отдельно: итог и статические тестовые кадры. DPR ограничен 2, каждый viewport buffer примерно 4 млн пикселей. Счётчик cache bytes измеряет RGBA backing, не всю память браузера, VRAM или JS heap.

Изменения инвалидируют затронутые плитки. TPL использует общую поверхность. После вытеснения данные восстанавливаются из контуров. Полный новый atlas из 96 пустых кадров не создаётся.

## Undo, файл и экспорт

Undo/Redo объединяет размещения одного жеста в одну операцию. Clear обратим. Новое рисование после Undo убирает Redo. История ограничена 100 действиями и оценкой 16 MiB геометрии, последнее действие сохраняется. История session-only.

Save strokes записывает JSON schema 2. Open сначала полностью проверяет формат, геометрию, параметры, размещения, порядок и бюджеты, затем заменяет документ. Ошибка оставляет текущую работу нетронутой. Сохранённый bbox пересчитывается по outline.

Schema 1 из drawing.2 принимается: исходные точки/outline сохраняются, назначается renderer linear-v1, единственное локальное размещение и прежние параметры. Старые контуры не сглаживаются заново. Исправление экранных стыков намеренно меняет ошибочное отображение при дробном zoom. Schema 2 не открывается в старом drawing.2.

Лимиты: 30 000 точек на штрих, 20 000 штрихов, 1 млн точек; раньше может сработать консервативная оценка файла 32 MiB. Текущие JSON и Open синхронные. Автосохранения нет. Перед закрытием страницы требуется Save.

PNG строится тем же tile renderer из сохранённой геометрии: Grid 1536 × 1296, Single 2048 × 1152; отдельный кеш 4 MiB освобождается после экспорта. Он не растягивает экранный preview как оригинал. Сглаживание на разных масштабах может отличаться; геометрия и порядок операций общие.

## Проверка качества и художественная приёмка

Проверены 31 unit test и 25 browser checks (9 основных, 7 дополнительных, 9 качества) на собранном HTML, обычный Edge 156.0.4314.42 через headless Playwright. Встроенный Codex preview не использовался как основание результата.

Форма сравнивается с независимым SVG-path из примера библиотеки: плавная кривая через 48 ячеек, редкий диагональный ввод и проход около угла. Потерянных внутренних пикселей не найдено. Растеризация полного пути и плиток имеет различия на сглаженных краях, не заявляется byte-identical изображение. Сырые допуски и результаты приведены в evidence.

Проверены фактическая ширина 12/96 px, отдельные параметры smoothing/streamline, один активный кадр Single, сохранность legacy-контура, отсутствие внутренних alpha-провалов на 12 комбинациях DPR/масштаба, синтетическое перо, настоящий браузерный download/reload/open, eraser, pinch, прерывание и экспорт.

Эмуляция телефона 390 × 844 включает не только tap: touch-жест пересекает 20 ячеек, остаётся одной геометрией и переживает Single/Undo/Redo. Это не физический iPhone/Android и не Safari/Pencil. RTX 5090 здесь не тестировалась.

Авторская проверка остаётся открытой: приятность следа, управляемость тонких линий, задержка при стабилизации, острые повороты, маленькие петли, медленная дрожащая линия и быстрые пересечения. Технический тест не может принять эти качества за автора.

## Версии, публикация и следующий этап

Метаданные лаборатории: `drawing-lab.release.json`, lab HTML/APP_VERSION, README и журнал. `npm run build:lab` создаёт только lab HTML и лицензии. Root package/lock и обычные HTML/APP_VERSION остаются drawing.2 по прямому указанию автора. Inter включён локально с OFL notice; ссылка на обычное приложение из шапки убрана.

GitHub Pages публикует только новый lab HTML и лицензии в версионную папку. Старые URL не переписываются. Vercel production не обновляется. Branch-specific git.deploymentEnabled отключает автоматический Vercel preview для drawing-engine и gh-pages; причина старого письма: попытка выполнить vite build в ветке с уже готовой статикой и без Vite. [Документация Vercel](https://vercel.com/docs/project-configuration/git-configuration).

Следующий шаг: автор проверяет эту ссылку на компьютере и физическом телефоне. Замечания сначала исправляются в стенде. После принятия характера кисти согласуем интеграцию с существующим TimeGrid, реальными кадрами, legacy raster и экспортом. Затем полный ProjectDocument, далее proxy. Новые сценарии/режимы и монетизация не расширяют эту итерацию.
